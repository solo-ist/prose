## The fault under the editor bugs

### What it is

Prose has one TipTap editor. A tab switch serialises the leaving document to markdown, re-parses the arriving one, and calls `setContent`. Comments, AI annotations and AI suggestions are not part of the document; each lives in its own global Zustand store, swapped on every switch, and each is re-attached to the new document by its own scheme: comments by text and occurrence index, AI annotations by raw position, suggestions by marks. The only thing that says which document a store currently belongs to is an `isLoadingDocument` timing flag and a `documentId` field that is set before the records that go with it arrive.

Every editor bug in the polish pass is a consequence of that shape:

| Bug | What the shape did |
|---|---|
| #1137 comment on the wrong occurrence | Two schemes counted occurrences differently; the next persist locked the wrong one in |
| #1138 annotation drift | Positions persisted raw; the re-parse renormalised text above them |
| #1126 suggestions came back | Persist path skipped an empty set it should have written |
| #1127 lost keystrokes | The switch read the store before the editor's debounce had written to it |
| #1102 source-mode round trip | The hidden editor echoed every source edit back through the sync effect |
| #1103 caret reset | The switch rebuilt editor state from scratch; nothing carried the view |
| Section G contamination | A persist landed between `setDocumentId(next)` and `loadAnnotations(next)`, writing the previous document's records under the next document's key |

The last row is the one that settles it. The store accepted a write for a document other than the one its records belong to, because nothing in the design ties records to a document except the order of two calls.

### How we got here

The symptoms were filed as separate issues, each fixed within its own files, each reviewed on its own diff. Every fix was correct against its issue and added one more writer to the shared stores. No single PR looked wrong, and no PR-level review can see that a store is being written from three places with a timing flag as the only guard. The countermeasure is not better patches. It is a design gate: any change that writes to shared editor state goes through a design that names who owns the state and what identifies it, before an issue is picked up.

### What would remove it

**Option 1. Per-tab editor state, annotations inside it.** Each tab owns a ProseMirror `EditorState`. Switching tabs calls `view.updateState(tab.state)`; nothing is serialised or re-parsed. Comments, AI annotations and suggestions live in plugin state inside that `EditorState`, so they map through the tab's own transactions and cannot see another tab's. Persistence is a projection of plugin state, keyed by the owning document, written only by that state. Re-anchoring by text happens in exactly one place: load from disk, where there is one document and no race. Source mode per tab and caret restore become properties of the state rather than features. This is the direction #1132 and the plan's "global singletons" note pointed at.

Scope: the content-sync effect in `Editor.tsx`, the tab hook, `tabStore`, the three annotation stores and their three plugins, the persistence layer's keying, and the places that read the stores directly (tool executors, review panels, share sync). Mostly renderer; no main-process or preload changes, so no security gate.

**Option 2. Keep one editor; make identity explicit.** Leave the re-parse model. Stamp every `EditorState` with its document id, make every store refuse a write for any other id, change the id and the records together in one call, and collapse the three anchoring schemes into one representation (text plus context, resolved once on load). Smaller, and it closes the contamination class and the occurrence class. It does not remove the re-parse, so drift re-anchoring stays, and the source-mode and caret problems keep their per-tab mirrors.

**Option 3. Option 2 now, Option 1 as the first item of the next epic.** The honest middle. It is also the shape that produced this epic: a guard now, the structural change later, with the later part competing against features.

### Recommendation

Option 1, in 1.9.0. The operator's own rule for this release was that the editor should be clean before the big epic starts, and the editor cannot be made clean on the current shape; it can only be made quieter. Option 1 also deletes code: the loading flag, the re-attach schemes, the per-tab mirrors, and most of the content-sync effect.

Acceptance is already written. The three probes from the last two days reproduce the drift, the occurrence miss and the contamination on demand; they become the suite. Add: a tab switch between two documents with annotations in both leaves each document's records untouched and keyed to itself, byte for byte.

Rules that hold from now on, whichever option is chosen:

1. No write to an annotation store without the document id of the state that produced it, and the store rejects a mismatch.
2. The document id and its records change in one call, never two.
3. No new timing flag as a guard for shared state.
4. Any change that touches shared editor state gets a design note naming the owner before implementation.

### What the decision changes in the outline

Choosing Option 1 moves section A behind one piece of design work and leaves section B to proceed in parallel. Choosing Option 2 unblocks section A sooner and carries #1132, #885 and the frontmatter effect forward on the old shape. Either way, section B and C do not wait.
