# #1223 — MAS: the real home, not the sandbox container

Issue: https://github.com/solo-ist/prose/issues/1223 · renderer half: #1222 (PR #1224).
Branch `issue-1223-mas-real-home` from `main` = `2d41a6d`. Security-gated (`src/main/**`): the operator reviews.

## Context

Under the App Sandbox, `HOME` is the app's container (`~/Library/Containers/ist.solo.prose/Data`). So are
`os.homedir()`, `app.getPath('home')` and `app.getPath('documents')`. The App Store still serves 1.6.5, so
two later changes have never run in the sandbox:

- `local-file:` (#918, v1.8.0) confines image reads to `homedir()`. Under the sandbox every image outside the
  container gets a 403, so **no image in a document loads** on the 1.9.0 App Store build.
- `dialogDefaultPath` (#1153, v1.9.0) falls back to `app.getPath('documents')`, which is the container's own empty
  Documents folder. A remembered folder outside the grant fails `stat()` and is skipped, so **Open and Save As start
  in a hidden folder**.
- `getToolRoots` (#918) and `expandPath` root at the container too: "open ~/notes/x.md" means the user's home.
- The MCP socket server starts on MAS, where nothing can reach it.

## Change

1. `paths.ts`: `userHomeDir()` is `os.userInfo().homedir` on MAS (the password database, so the real home) and
   `homedir()` otherwise. `userDocumentsDir()` is `<real home>/Documents` on MAS and `app.getPath('documents')`
   otherwise. `expandPath`, `getToolRoots` and the `local-file:` root use `userHomeDir()`. The app's own data
   (`getUserDataPath`, the settings directory, the legacy `~/.prose` migration) is untouched and stays in the
   container. The sandbox still decides what can be read; these are roots and hints, not grants.
2. `dialogDirs.ts`: the fallback chain is remembered → default save directory → `userDocumentsDir()` →
   `userHomeDir()`. `isDirectory` counts `EPERM`/`EACCES` as present: the system picker runs outside the
   sandbox, so a starting-folder hint needs no grant.
3. `index.ts`: no MCP socket server on MAS.
4. `resources/PrivacyInfo.xcprivacy`: FileTimestamp reasons `C617.1` (container files) and `3B52.1` (user-granted
   files) beside `DDA9.1`.

## Tests

- vitest `src/main/paths.home.test.ts`: `userHomeDir`/`expandPath` per edition, with `env`, `os` and `electron`
  mocked. vitest `src/main/dialogDirs.test.ts`: remembered and fallback folders, `EPERM` accepted, `ENOENT`
  skipped, the MAS fallback is the real Documents. `env.ts` is generated by the build and CI runs unit tests
  first, so both files mock `./env`.
- e2e `electron.mas-home.spec.ts` (MAS-flagged build, skipped otherwise): launched with `HOME` set to a scratch "container",
  an image under the real home renders. On the merge-base it gets a 403.
- TestFlight (`docs/qa/v1.9.0-mas.md`) is the real-sandbox gate.
