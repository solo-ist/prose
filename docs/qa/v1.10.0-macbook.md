# 1.10.0 — final checks on the MacBook

> This release was called 1.9.1 until 2026-11-16. The branch is still named `release/v1.9.1`.

Written 2026-11-16. Everything that could be checked on the Mac Studio is ticked in `docs/qa/v1.10.0.md`; this is what is left, in the order to run it. Box wording matches the full checklist where a box came from it, so ticks carry back.

Branch: `release/v1.9.1`, at the commit "Release is 1.10.0" or later.

## 0. Build

```bash
git fetch origin && git checkout release/v1.9.1 && git pull
git log --oneline -3          # includes "Release is 1.10.0"
npm ci
npm run build:mas             # → dist/mas-arm64/Prose-<version>-arm64.pkg
npx electron-builder --mac mas-dev   # optional: dist/mas-dev-arm64/Prose.app, to run locally without TestFlight
```

- [ ] **Version.** `package.json` says `1.10.0` and `electron-builder.yml` has `buildVersion: "34"`. Raise the build number again for any second upload, or App Store Connect refuses it as a duplicate.
- [ ] The build finishes with no signing or provisioning error.
- [ ] Upload to TestFlight (Transporter, or `xcrun iTMSTransporter -m upload`). Upload only: submitting for review is a separate decision.

## 1. The App Store build

On the TestFlight (or `mas-dev`) build of 1.10.0.

### Upgrading from 1.9.0

Install over an App Store 1.9.0 that has been used: two open tabs, a comment, an AI edit, an API key.

- [ ] It launches with no "Database Recovery Occurred" dialog. (1.10.0 raises the local database from version 10 to 11.)
- [ ] Both tabs reopen; the comment and the AI edit's highlight are on their text.
- [ ] The Anthropic key is still there (Settings → LLM shows **Key saved ••••xxxx**) and chat answers.
- [ ] "What's new" opens once after the update and shows the App Store notes for 1.10.0: Models, Suggesting mode, Who did what, Fixes. Nothing about MCP, Remote access, sharing or Claude Desktop.

### What the App Store build must not have

- [ ] The App Store build (TestFlight of 1.10.0): no Integrations tab, so no Remote access, and nothing connects to the relay.
- [ ] The App Store build itself (TestFlight of 1.10.0) shows no import offer and no Settings row.
- [ ] Settings → General → Email (optional): the hint reads "Stays on this Mac: it is never stored on your comments or sent to agents", with no mention of sharing.
- [ ] No sharing (no ◎ share control, no gateway sign-in) and no update check.

### What it must have

- [ ] The App Store build (TestFlight of 1.10.0): the same LLM tab, both providers, nothing missing.
- [ ] **The OpenAI list is GPT-5.5 and newer (#1311).** With an OpenAI key saved, the model list shows only `gpt-5.5`, `gpt-5.6-luna`, `gpt-5.6-sol`, `gpt-5.6-terra`, `gpt-6-luna`, `gpt-6-sol`, `gpt-6.1-terra` (plus anything newer OpenAI has added). No gpt-4o, gpt-5, o3, dated snapshots, `gpt-6-astra` or `gpt-6.1-sol`.
- [ ] Pick a GPT model and ask the chat "Which model are you?", then for an edit to a paragraph. Both work.
- [ ] Pick a Claude model: chat goes back to Anthropic and an edit suggestion lands for review.
- [ ] **Suggesting mode.** Click the pen button, type a few words mid-sentence: they are underlined, the status bar says **1 suggestion**, and the tab has no unsaved dot. Accept it in Quick Review; ⌘S writes it.
- [ ] Open, edit and save a file in a folder you choose; quit and relaunch: the file reopens without a permission prompt.

## 2. The direct build beside the App Store edition (W1, #1243)

Only if you also make the signed direct build on the MacBook (`npm run build:mac`). Needs the **App Store edition 1.9.0 installed** and used for a while (a project, a favorite, two open tabs, an AI edit, a comment, an API key).

**0. Signing requirements first.**

```bash
codesign -d -r- "/Applications/Prose.app"                       # the App Store edition
codesign -d -r- "<path to the direct build>/Prose.app"          # this branch's direct build
```

- [ ] Both print a designated requirement; note whether each names the team id `8PT2Y7QQ2F` and how they differ.

**1. First launch offers the import.** Quit the App Store edition. Install the direct build somewhere other than `/Applications` and launch it on a profile it has never used (`~/Library/Application Support/Prose` absent, or moved aside).

- [ ] Launching shows **no** macOS "Prose would like to access data from other apps" prompt before you click anything.
- [ ] "Moving from the App Store edition?" appears before the onboarding.
- [ ] With the App Store edition **open**, Import and restart says to quit it first and does nothing.
- [ ] With it quit, Import and restart restarts Prose. If macOS asks about accessing data from other apps here, note it.
- [ ] After the restart: "Imported from the App Store edition"; no onboarding, no "What's new".
- [ ] Projects, favorites, recent files and both open tabs are there; the AI edit's highlight and the comment are on their text; Settings (appearance, editor) match the App Store edition.
- [ ] **Bring my key over**: note whether macOS asks about "Prose Safe Storage", and whether the key arrives ("Your API key is set") or Prose asks you to enter it again. Either is acceptable; a hang or a crash is not.
- [ ] AI works afterwards (with the brought-over key or a re-entered one).
- [ ] `~/Library/Application Support/Prose/app-store-import.json` lists what was copied; there is no `credentials/` file you did not create here, no `app-store-import/` folder after the key step.
- [ ] The App Store edition still opens with all its data (copy, never move).

**2. Not now, and the Settings route.**

- [ ] On another fresh profile, Not now → onboarding runs; relaunch → no offer.
- [ ] Settings → General shows "App Store edition — Import…"; the confirmation mentions the backup folder; Cancel changes nothing.
- [ ] With a document dirty, Import and restart asks you to save or close it first.
- [ ] After an import from Settings, `before-app-store-import-<time>/` holds what was replaced.

**3. Edges.**

- [ ] If any recent file lived inside the App Store container, the summary lists it.
- [ ] On a Mac without the App Store edition, nothing about it appears anywhere (no offer, no Settings row).
