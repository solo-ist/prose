## What this build is, and what it isn't

**It cannot touch your real Prose.** The QA app runs under its own identity
(`ist.solo.prose.qa`, app name `prose-qa`), so it gets its own profile at
`~/Library/Application Support/Prose QA` — separate settings, separate document
list, separate IndexedDB, separate single-instance lock, separate MCP socket.
Your installed Prose and its documents are untouched. Your markdown files on
disk are shared, of course — they're just files.

Three consequences of that isolation worth knowing before you start:

- **The profile starts empty.** That is itself the fresh-install test (#1051).
- **Your API key doesn't carry over.** safeStorage keys its keychain item by app
  name, so the QA app has no key. You'll paste one in Settings → LLM — your
  step, not mine.
- **Auto-update is inert.** A `dir`-target build ships no `app-update.yml`, so
  the log line `[Updater] Initial check failed: ENOENT … app-update.yml` is
  expected, every launch. It also means this build will never offer to
  "update" you back to 1.8.2.

**Quit the installed Prose before you start.** Two reasons: the MCP HTTP server
binds `127.0.0.1:9877` and whichever app starts first wins (the loser logs
`EADDRINUSE`, which is expected, not a defect), and two pilcrows in the Dock is
a good way to test the wrong app for twenty minutes.

## 8 · #1060 — table editing

Before this there was **no table UI at all** — the extensions were registered and
the markdown round trip worked, but nothing could create or change a table except
typing pipes by hand. So everything here is new surface.

**The invariant that matters more than the UI:** `tiptap-markdown` silently falls
back to emitting the whole table as **raw HTML** if the first row stops being all
header cells, any cell gains a colspan/rowspan, or any cell ends up holding more
than one block (`tiptap-markdown/src/extensions/nodes/table.js:58-73`). That turns
the user's markdown file into an HTML blob with no error and no warning. Every
operation below is therefore followed by *save and look at the file on disk* —
that check, not the on-screen result, is what this section is really testing.

Work in a scratch file you don't mind mangling, and keep a second terminal
tailing it so you can see the markdown change as you edit (`watch` isn't on
macOS, so this is the loop form):

```sh
while :; do clear; tail -20 ~/Documents/table-qa.md; sleep 1; done
```

- [ ] **Insert.** Edit → **Insert Table** (deliberately no keyboard shortcut —
      every obvious binding was already taken). You should get three columns and
      three rows: a **header row plus two body rows**, the smallest table that
      shows its own structure.
- [ ] Type into cells; Tab and the arrow keys move between them.
- [ ] **Append.** The `+` at the right edge adds a column; the `+` at the bottom
      edge adds a row. Both should keep the header row intact.
- [ ] **The rails appear on hover.** This changed in #1087 — the caret alone no
      longer reveals them, which is what section 13 tests. Hover the table:
      grips appear in the **left gutter, one per row**, and along the **top, one
      per column**, all at once. Move the pointer away and they go. Don't test
      the old caret behaviour here; section 13 owns it.
- [ ] **Row grip.** Click a row's grip: the row selects and a small toolbar opens
      with **move up / move down / delete**.
- [ ] **Column grip.** Same from a column grip, with move left / move right /
      delete.
- [ ] Move a row down and a column right; the content moves with them.
- [ ] **Delete is behind the selection, not a bare `−`.** Delete a body row and a
      column.
- [ ] **Deleting the header row doesn't break the table** — it promotes the next
      row into the header, so the file still leads with a header and still
      serializes as pipes. Delete it, then run the two greps below.
- [ ] **A one-row or one-column table won't delete down to nothing** — with a
      single row (or column) left, delete should be unavailable rather than
      leaving an empty husk.
- [ ] **After *each* of the operations above:** ⌘S, then confirm the file on disk
      is still a pipe table, not HTML:

      ```sh
      grep -c '^|' ~/Documents/table-qa.md     # > 0
      grep -c '<table' ~/Documents/table-qa.md # must be 0
      ```

- [ ] **Enter inside a cell.** Press Enter mid-cell: you should get a line break
      *inside* the cell, not a second paragraph. Save and re-check with the two
      greps above — this is the case that used to convert the table to HTML on the
      very first Enter.
- [ ] Reopen the file: the table comes back as a table, with the line break intact.
- [ ] **Source mode round trip.** Toggle to source mode and back. The table
      survives, and **no grips or `+` controls appear while in source mode**.
- [ ] Rails don't fight the other decorations: add a comment on text inside a
      cell, then click back into the table — the grips still appear and the
      comment highlight is still there.
- [ ] AI edits still refuse to touch tables: with tool mode **Full**, ask the AI
      to change a cell. It should decline rather than mangle the table (that guard
      is deliberate and unchanged).

## 11 · #1063 — the delivered Prose mark, in-app

The mark used to be *synthesized*: a `¶` character set in Fraunces italic inside a
CSS squircle, screenshotted through a headless browser at build time. That made
the app's identity depend on a Google Fonts fetch and on a working Playwright
Chromium install. It's now the vector outline from the same `AppIcon.icon` bundle
the app icon is built from, so the in-app mark and the shipped icon are one
drawing rather than two things that resemble each other.

- [ ] **About** (Prose → About Prose): the mark is the rounded tile — cream glyph
      on near-black. Compare it with the Dock icon; they should be the same
      drawing.
- [ ] **Empty state.** Close all tabs to reach "Start Writing": the glyph appears
      in muted grey. Zoom in (⌘+ a few times or a screenshot at 2×): the strokes
      should be clean vector edges, not the soft fringe of a resampled screenshot.
- [ ] **AI avatars** — all four readers: send a chat message, open a comment
      thread popover, open the comment review panel, and open the AI-edits history
      panel. The same mark in each.
- [ ] All six places show the *same* drawing — they render one component now,
      so a difference between any two of them is a real defect.
- [ ] No red console errors on any of those surfaces.

The font dependency itself isn't something you can usefully check by hand (it
only showed when Fraunces hadn't loaded yet). It's asserted in e2e instead: the
icon module is checked for any surviving `Fraunces` declaration.

## Found while building this

`src/main/mcp/socket-server.ts:20` computes the MCP socket directory at module
load, before `index.ts` applies the userData override — the exact invariant
`paths.ts` documents. It means a dev or e2e launch writes (and *unlinks*) the
socket inside the **installed** app's profile, which breaks Claude Desktop's
MCP connection to the running app until that app restarts.

It doesn't affect this QA build (which isolates by app name rather than by the
env seam) or the shipped app. It's filed as **#1049** — I first filed it as
#1070, then found #1049 already described it and covers the shared 9877 port
too, so the evidence moved there and #1070 is closed as a duplicate.
