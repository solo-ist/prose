## What this build is, and what it isn't

**It cannot touch your real Prose.** The QA app runs under its own identity
(`ist.solo.prose.qa`, app name `prose-qa`), so it gets its own profile at
`~/Library/Application Support/Prose QA` — separate settings, separate document
list, separate IndexedDB, separate single-instance lock, separate MCP socket.
Your installed Prose and its documents are untouched. Your markdown files on
disk are shared, of course — they're just files.

Three consequences of that isolation worth knowing before you start:

- **The profile starts empty.** That is itself the fresh-install test (#1051).
- **Your API key doesn't carry over.** safeStorage keys its keychain item by app
  name, so the QA app has no key. You'll paste one in Settings → LLM — your
  step, not mine.
- **Auto-update is inert.** A `dir`-target build ships no `app-update.yml`, so
  the log line `[Updater] Initial check failed: ENOENT … app-update.yml` is
  expected, every launch. It also means this build will never offer to
  "update" you back to 1.8.2.

**Quit the installed Prose before you start.** Two reasons: the MCP HTTP server
binds `127.0.0.1:9877` and whichever app starts first wins (the loser logs
`EADDRINUSE`, which is expected, not a defect), and two pilcrows in the Dock is
a good way to test the wrong app for twenty minutes.

## 1 · #1051 — the v1.2 migration toast is gone

The toast is deleted outright, so the fresh-install case is the easy half. The
interesting half is a *stale* profile, because that's the only path that ever
set `migrationToastShown: false`.

- [x] **Fresh profile** (you're already in one): no migration toast, no
      theme/icon prompt, anywhere in the first run.
- [x] **Stale profile.** Quit the QA app, then seed a legacy v1.1 `theme` key —
      the only path that ever wrote `migrationToastShown: false`:

      ```sh
      python3 - <<'PY'
      import json, pathlib
      p = pathlib.Path.home() / 'Library/Application Support/Prose QA/settings.json'
      s = json.loads(p.read_text()) if p.exists() else {}
      s['theme'] = 'termy-green-dark'   # v1.1 shape, triggers the migration
      s.pop('appearance', None)         # legacy key wins, so clear the new one
      p.write_text(json.dumps(s, indent=2))
      print('seeded', p)
      PY
      ```

- [x] Relaunch: still **no toast**, and the theme migrates (you should land in
      the Termy green dark palette, not Mono light).

## 5 · #1054 — partial selections no longer carry their block marker

**Paste outside Prose, or the bug is masked.** In-app paste uses the `text/html`
flavour, which was always correct; the broken flavour was `text/plain`. TextEdit

Paste this into a QA document first:

```md

- First bullet with several words
- Second bullet with several words

```

The fix must do two things: strip markers where the selection is *inside* one
block, and leave markdown alone where it legitimately spans blocks.

- [x] Select the middle few words of the **first bullet** → copy → paste into

- [x] Same inside the **blockquote** → no `>`.

- [x] Partial selection inside the **code block** → no fence.
- [x] Now the no-regression half: select a **whole bullet** → paste → the `-`

- [x] Select **both bullets** → paste → both markers, no phantom indentation

- [x] Select **heading + paragraph together** → paste → the `#` survives.

## Expected in this build — not defects

- `[Updater] … app-update.yml` ENOENT on every launch (no update channel in a
  `dir` build).
- `[MCP HTTP] Port 9877 is already in use` if another Prose is running.
- The Dock/About icon is the **current** rendered pilcrow, not the new vector
  mark — that's #1063 and #812, neither of which is in this build.
- About reports `1.9.0` on a branch whose `package.json` bump is QA-local.
- A `[Paths] WARNING: getUserDataPath() returned ".../prose" but
  app.getPath('userData') returned ".../Prose QA"` on every launch. This is an
  artifact of renaming the QA build, not a product bug — the shipped app's two
  names agree, so it never fires there.

  It is worth one correction to what I told you above, though. `getUserDataPath()`
  hardcodes the production profile name, and one thing calls it *before* the
  rename takes effect: the pre-ready Sentry init, which reads `settings.json` to
  decide whether error reporting is on. So this QA build reads **your real
  profile's settings.json once at startup**, read-only, for that one decision —
  meaning it inherits your real error-tracking opt-in rather than starting from
  the default. Nothing is written there: the `app.setPath` redirect only fires
  for `PROSE_USER_DATA_DIR` or dev, so every write (settings, IndexedDB, caches,
  the lock, the socket) still goes to `Prose QA`. Isolation for writes is intact;
  that single read is the one exception to "separate settings".

## Found while building this

`src/main/mcp/socket-server.ts:20` computes the MCP socket directory at module
load, before `index.ts` applies the userData override — the exact invariant
`paths.ts` documents. It means a dev or e2e launch writes (and *unlinks*) the
socket inside the **installed** app's profile, which breaks Claude Desktop's
MCP connection to the running app until that app restarts.

It doesn't affect this QA build (which isolates by app name rather than by the
env seam) or the shipped app. It's filed as **#1049** — I first filed it as
#1070, then found #1049 already described it and covers the shared 9877 port
too, so the evidence moved there and #1070 is closed as a duplicate.
