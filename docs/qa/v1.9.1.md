# 1.9.1 QA

One block per PR of epic #1230 (https://github.com/solo-ist/prose/issues/1230). Tick in Prose; a note under a box is a finding.

## P1 (#1232): who made each record

On the dev server (`qa/dev`), any document.

- [ ] Settings → General shows **Your Name** and **Email (optional)**. Set a name, Save Changes.
- [ ] Select text, add a comment: the popover names you by that name; with the name cleared, it says "You".
- [ ] Reply in the popover: the reply carries your name too.
- [ ] Ask the in-app chat to comment on a paragraph: the comment says "Prose · <model>" (for example "Prose · Sonnet 5.5"), not "Prose" alone.
- [ ] From Claude Desktop (or another MCP client), add a comment: it says "MCP client".
- [ ] Have the chat suggest an edit: the suggestion popover shows "By Prose · <model>". Accept it: the AI highlight's tooltip and its Activity row name the same agent instead of a bare model id.
- [ ] Mark a selection as AI-written (selection popover): Activity says "Imported".
- [ ] Open a document you commented on before this build: your old comments show your name, old AI comments show "AI", and a share reviewer's comment shows their name (it used to say "you" when expanded in Activity).
- [ ] Quit and relaunch: every name above is still right.

## P2 (#1233): the review log

The log has no UI of its own until P4 (#1234) lists it in Activity, and agents read it through M4 (#890). These checks use the dev tools console (`PROSE_DEBUG=1`) or wait for P4.

- [ ] Ask the in-app chat to suggest an edit, give it feedback in the suggestion popover, then accept it. `__prose_tools.getReviewLog()` shows the suggestion as accepted (by you), with your feedback entry, and four events in order: proposed, feedback, accepted.
- [ ] Reject a suggestion, then press ⌘Z. The log shows it rejected and then reopened, and the rejection stays in the events.
- [ ] Delete the text a suggestion covers. The log shows it rejected by you.
- [ ] Comment, have the chat reply, resolve it. The log has added, replied and resolved, each with the right actor.
- [ ] Quit and relaunch: the log reads back the same.

## M3 (#1237): MCP targeting and manners

From Claude Desktop, Claude Code or another MCP client connected to the dev build, with two documents open in Prose.

- [ ] Ask the client to `list_tabs`, then to comment on the tab you are **not** looking at (it passes that tab's `document`). The comment lands there; your tab stays in front.
- [ ] While you type in the chat panel, have the client comment on the document in front of you. The comment appears; your text, caret and focus stay in the chat input.
- [ ] With your caret mid-sentence in the editor, have the client suggest an edit to another paragraph. The suggestion appears; your caret doesn't move.
- [ ] Ask the client to comment on a file that isn't open. It gets "No open document matches…" and no tab opens. `open_file` still opens it, and switches to it, as before.

## M4 (#890): MCP review tools

From an MCP client (Claude Desktop, Claude Code, Codex) connected to the dev build.

- [ ] Ask the client to suggest an edit. In Prose, leave feedback on it in the suggestion popover. Ask the client to `list_suggestions`: it sees your feedback, attributed to "the writer".
- [ ] Ask it to answer your feedback (`reply_to_suggestion`) and then `revise_suggestion`. The old suggestion disappears and the revised one appears on the same paragraph.
- [ ] Accept the revision in Prose. Ask the client for `list_review_events`: proposed, feedback, feedback, revised, accepted, each with who did it. Asked again with `since` set to the last seq, it reports nothing new.
- [ ] Ask the client to accept a suggestion. It can't: it has no accept tool, and the call is refused.
- [ ] Resolve a comment the client left, then have it reply and `reopen_comment`. The thread is open again with its highlight.

## P4 (#1234): Activity over the review log

- [ ] Have the in-app chat suggest an edit, give feedback, have an MCP client revise it, and accept the revision. Activity shows one **Superseded** row ("Revised by <client>") and one **Accepted** row ("Accepted by <your name>"). Clicking the superseded row shows your feedback.
- [ ] A pending suggestion's row opens Quick Review on that suggestion.
- [ ] The filter menu has **Suggestions: Pending / Decided** and **People and agents**. Picking an MCP connection shows only what it made or touched, and the badge follows. Show all resets everything.
