# 1.9.1 QA

One block per PR of epic #1230 (https://github.com/solo-ist/prose/issues/1230). Tick in Prose; a note under a box is a finding.

## P1 (#1232): who made each record

On the dev server (`qa/dev`), any document.

- [ ] Settings → General shows **Your Name** and **Email (optional)**. Set a name, Save Changes.
- [ ] Select text, add a comment: the popover names you by that name; with the name cleared, it says "You".
- [ ] Reply in the popover: the reply carries your name too.
- [ ] Ask the in-app chat to comment on a paragraph: the comment says "Prose · <model>" (for example "Prose · Sonnet 5.5"), not "Prose" alone.
- [ ] From Claude Desktop (or another MCP client), add a comment: it says "MCP client".
- [ ] Have the chat suggest an edit: the suggestion popover shows "By Prose · <model>". Accept it: the AI highlight's tooltip and its Activity row name the same agent instead of a bare model id.
- [ ] Mark a selection as AI-written (selection popover): Activity says "Imported".
- [ ] Open a document you commented on before this build: your old comments show your name, old AI comments show "AI", and a share reviewer's comment shows their name (it used to say "you" when expanded in Activity).
- [ ] Quit and relaunch: every name above is still right.

## P2 (#1233): the review log

The log has no UI of its own until P4 (#1234) lists it in Activity, and agents read it through M4 (#890). These checks use the dev tools console (`PROSE_DEBUG=1`) or wait for P4.

- [ ] Ask the in-app chat to suggest an edit, give it feedback in the suggestion popover, then accept it. `__prose_tools.getReviewLog()` shows the suggestion as accepted (by you), with your feedback entry, and four events in order: proposed, feedback, accepted.
- [ ] Reject a suggestion, then press ⌘Z. The log shows it rejected and then reopened, and the rejection stays in the events.
- [ ] Delete the text a suggestion covers. The log shows it rejected by you.
- [ ] Comment, have the chat reply, resolve it. The log has added, replied and resolved, each with the right actor.
- [ ] Quit and relaunch: the log reads back the same.

## M3 (#1237): MCP targeting and manners

From Claude Desktop, Claude Code or another MCP client connected to the dev build, with two documents open in Prose.

- [ ] Ask the client to `list_tabs`, then to comment on the tab you are **not** looking at (it passes that tab's `document`). The comment lands there; your tab stays in front.
- [ ] While you type in the chat panel, have the client comment on the document in front of you. The comment appears; your text, caret and focus stay in the chat input.
- [ ] With your caret mid-sentence in the editor, have the client suggest an edit to another paragraph. The suggestion appears; your caret doesn't move.
- [ ] Ask the client to comment on a file that isn't open. It gets "No open document matches…" and no tab opens. `open_file` still opens it, and switches to it, as before.

## M4 (#890): MCP review tools

From an MCP client (Claude Desktop, Claude Code, Codex) connected to the dev build.

- [ ] Ask the client to suggest an edit. In Prose, leave feedback on it in the suggestion popover. Ask the client to `list_suggestions`: it sees your feedback, attributed to "the writer".
- [ ] Ask it to answer your feedback (`reply_to_suggestion`) and then `revise_suggestion`. The old suggestion disappears and the revised one appears on the same paragraph.
- [ ] Accept the revision in Prose. Ask the client for `list_review_events`: proposed, feedback, feedback, revised, accepted, each with who did it. Asked again with `since` set to the last seq, it reports nothing new.
- [ ] Ask the client to accept a suggestion. It can't: it has no accept tool, and the call is refused.
- [ ] Resolve a comment the client left, then have it reply and `reopen_comment`. The thread is open again with its highlight.

## M1 (#1235) — MCP protocol on the v2 SDK

Run against the dev window (port **9878**) before merge, or the installed app (port **9877**) after a release.
The token rotates on every launch until M2 (#1236), so re-read it after a restart.

```sh
PROFILE="$HOME/Library/Application Support/Prose Dev"   # installed app: .../Prose
TOKEN=$(cat "$PROFILE/mcp-auth-token"); PORT=9878        # installed app: 9877
```

- [ ] **Health and info.** `curl -s http://127.0.0.1:$PORT/health` → `{"status":"ok"…}`;
      `curl -s -H "Authorization: Bearer $TOKEN" http://127.0.0.1:$PORT/` shows the app version (1.9.x, not 1.0.0) and
      `protocolRevisions: ["2026-07-28","2025-11-25"]`.
- [ ] **Rebinding guard.** `curl -s -o /dev/null -w "%{http_code}\n" -H "Host: attacker.example" -H "Authorization: Bearer $TOKEN" -X POST http://127.0.0.1:$PORT/mcp`
      → `403`. The same with `-H "Origin: https://attacker.example"` instead of the Host header → `403`.
- [ ] **Docker clients, still behind the token.** `docker run --rm curlimages/curl -s -o /dev/null -w "%{http_code}\n" -X POST http://host.docker.internal:$PORT/mcp`
      → `401`; the same with `-H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" -H "Accept: application/json, text/event-stream" -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'`
      → `200` (how Open WebUI and LibreChat in Docker reach the app).
- [ ] **Two instances, two ports.** With the installed Prose and the dev window both running, each answers on its own
      port (9877 and 9878) with its own token; neither logs `Port … is already in use`.
- [ ] **Claude Code.** `claude mcp add --transport http prose-qa http://127.0.0.1:$PORT/mcp --header "Authorization: Bearer $TOKEN"`,
      then in Claude Code: "list my Prose tabs" → the tabs of that window. `/mcp` shows the server connected with
      10 tools. Remove it afterwards: `claude mcp remove prose-qa`.
- [ ] **Codex.** In `~/.codex/config.toml`:
      `[mcp_servers.prose_qa]` / `url = "http://127.0.0.1:9878/mcp"` / `bearer_token_env_var = "PROSE_QA_TOKEN"`,
      then `PROSE_QA_TOKEN=$TOKEN codex` → "read the active Prose document" returns its text. Remove the block afterwards.
- [ ] **Claude Desktop (stdio).** Settings → Integrations shows the MCP server needs an update (the bundled bridge
      changed); update, restart Claude Desktop, and ask it to list Prose tabs. Tool cards show titles ("List tabs").
- [ ] **A suggestion still lands for review.** From any client above: read the document, then suggest an edit to
      one paragraph → the suggestion appears in Prose for you to accept or reject.

## M2 (#1236) — MCP connections

On the dev window (port **9878**) before merge, or the installed app (port **9877**) after a release. Settings →
Integrations → **Connections**.

- [ ] **Add.** Type a name ("Codex on this Mac"), Add: the token appears once with a copy button and the row shows
      "Never used". The setup tabs (Claude Code, Codex, Open WebUI, LibreChat) show this window's URL and, until Done,
      the new token. Done hides the token for good; the snippets fall back to `<your connection token>`.
- [ ] **Names.** Adding a second connection with the same name (any case) is refused with a message; so is a blank one.
      Rename a connection (pencil): the row updates.
- [ ] **Claude Code.** Paste the Claude Code snippet into a terminal, then ask Claude Code to comment on a paragraph of
      the open document. The comment in Prose names the **connection** ("Codex on this Mac" or whatever you called it),
      not "MCP client"; the row's "Last used" updates when you reopen Settings.
- [ ] **Codex / Open WebUI / LibreChat** (whichever you use): the same, with that tab's snippet. From Docker, the
      `host.docker.internal` URL in the snippet reaches the app.
- [ ] **Survives a restart.** Quit and relaunch Prose: the client keeps working with the same token (the launch token
      would not have).
- [ ] **Revoke.** Trash icon → Revoke: the client's next call fails (Claude Code reports 401 / unauthorized), and its
      earlier comments still name the connection.
- [ ] **Claude Desktop (stdio).** After updating the MCP server (Integrations shows "Update available"), a comment
      made from Claude Desktop names Claude Desktop's own client name (for example "claude-ai"), not "MCP client".
- [ ] **The token file.** `ls -l "$PROFILE/mcp-connections.json"` → `-rw-------`; it contains no `prose_mcp_` token.
