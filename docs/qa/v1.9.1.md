## A1 (#1240) — provider layer; keys stay in main

Setup: a profile that already has an Anthropic key saved (the `Prose Dev` profile does).

1. [ ] Launch. Chat works as before: send a message, the reply streams, and an edit tool call lands.
2. [ ] Settings (⌘,) → LLM shows **Key saved ••••••••xxxx** with your key's last four, and **Test** says the key is valid.
3. [ ] **Replace** shows the key field; **Keep saved key** returns to the saved line without changing anything.
4. [ ] **Replace**, type a wrong-format key: the amber format message shows and **Save Changes** is disabled. Type your real key, click **Test** (valid), then **Save Changes**; reopen Settings → LLM: the saved line shows the same last four.
5. [ ] **Clear**: the saved line goes, the field reads "API key is required", the chat input says AI isn't configured, and the Emoji Tab Icons switch is disabled. Re-enter the key and **Save Changes**; chat works again.
6. [ ] Type a key and close the dialog with **Cancel**: nothing is saved (the saved line, or the empty field, is unchanged when you reopen).
7. [ ] Tab emoji (Settings → LLM → Emoji Tab Icons on): a new tab with a title gets an emoji.
8. [ ] Document summary (the ⓘ in the chat header) generates.
9. [ ] With DevTools (`PROSE_DEBUG=1`), `await window.api.loadSettings()` in the console shows `llm.keyStatus` and **no** `apiKey`.
10. [ ] Onboarding (fresh profile: quit, launch with an empty `PROSE_USER_DATA_DIR`): the API key step verifies a key and says "Saved to Keychain"; after Done, chat works without visiting Settings.
11. [ ] reMarkable sync (if you use it): OCR still runs with the LLM key.
